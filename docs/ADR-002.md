# ADR-002 — Redis Cache + RabbitMQ Broker

**Status:** Accepted
**Formal Specification:** [docs/infra/REDIS_RABBITMQ_CONTRACTS.md](infra/REDIS_RABBITMQ_CONTRACTS.md) (GRU-57)

## Context & Decision
1. **Redis** serves exclusively as the low-latency volatile cache, distributed lock/lease coordinator, rate-limiting, and idempotency fast-path layer. Redis is strictly non-authoritative; PostgreSQL remains canonical.
2. **RabbitMQ** is the primary operational message broker for call dispatching, asynchronous external tool jobs, transcript persistence, and dead-letter handling.
3. **Transactional Outbox:** Critical events crossing service boundaries are persisted atomically to PostgreSQL within the domain transaction and relayed asynchronously to RabbitMQ, eliminating dual-write failure modes.
4. **Zero-PCM Path & Latency Objective:** Under no circumstances may Redis, RabbitMQ, PostgreSQL, or n8n carry PCM or audio frames. Audio frames flow strictly between Asterisk, AudioSocket, Go Voice Engine, and Gemini Live WSS with an end-to-end conversational round-trip latency objective < 800ms.
5. **Deterministic Stage-Based Retry:** Retries use dedicated delay queues with fixed TTLs (`call.retry.30s`, `call.retry.120s`, `call.retry.600s`) dead-lettering back to `voice.commands` (`call.dispatch`). Unrecoverable, poison, or exhausted retries ($\\ge 3$) route to `voice.dlx` (`voice.dead`).
